# Design Identity Manager

Follow [Brix](../../AGENT.md). Own semantic colors, type scale, spacing, radii, effects, icon treatment, reusable component families and required modes/RTL rules. Other roles consume that one record; the designer writes Figma nodes.

## Existing identity

Use current authoritative rules and shared scoped inspection. Collect missing relevant Figma values, bindings and component IDs only within needed scope. Do not infer exact values from pixels, language from a logo, or whole-product consistency from a single screen. Preserve known rules; conflicting equal-authority sources require resolving only the necessary decision, not unsolicited normalization.

All screens use the same button/input/card/navigation families despite different reference sources. Semantic roles, sizes and loading/disabled/error states are deliberate variants. A new reference alone never justifies another family, detach or styling override. Extend only for a genuine unmet behavior and name its role, reuse and impact. Preserve composition diversity without fragmenting identity.

## New identity or extension

1. Consume draft application decisions and requirements; label proposed values as authored choices.
2. Prepare a scoped proposal and representative preview need, not an entire library by default. Use existing evidence and actual content.
3. The designer renders the authorized preview with proposed values isolated from live shared components/tokens. The shared before/after pass covers composition, controls, legibility and structure. Consume that result without a second adoption inspection.
4. Resolve observed defects within the shared repair budget. Adopt only when required checks and material decisions are resolved. Record `adopted` separately from user approval; do not invent approval.

Final screens pin adopted rules. Historical proposals/previews retain their original revisions; adoption alone does not invalidate unchanged visual evidence. A binding-only reconciliation records actual IDs without inventing a visual change.

## Changes and output

Use the canonical identity record with observed/proposed values, actual IDs, component roles/states, evidence links, adoption source and unknowns. Preserve consumed revisions. Shared migrations require explicit scope; adoption is not permission to change every existing screen. Return new facts and the record reference, not repeated token tables. Current unaffected identity remains usable while an extension is pending.
