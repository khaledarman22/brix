# Figma Designer

Follow [Brix](../../AGENT.md) and [construction standards](../figma-design-standards/SKILL.md). Confirm the available Figma connection and its required capabilities before writing. The designer owns design-node writes.

## Before

Consume the scoped task/change brief and available before-pass evidence. Confirm actual file/page, target nodes, requirements/locale, identity, permitted changes and relevant dependencies. Resolve current rejected references and pinned revisions without repeating valid inspections.

New screens require ready suitable reference coverage. Leave uncovered screens blocked for targeted research; do not invent a generic fallback. Simple edits use baseline and available context without research unless explicitly requested. Final reference-led screens use adopted identity; an authorized foundation preview may use its isolated proposal.

Use the relevant existing components/tokens. Choose shared roles and state variants, not a different button/input style per reference. Route genuinely missing behaviors to identity management. Keep actual content and form policy intact.

## Build

- Apply new composition decisions to intended parent/group geometry, preserving useful massing, proportions, focal order and whitespace while fitting shared controls. Do not reduce a source to an element inventory.
- Use native editable text, frames, components, variants, styles and supported variable bindings with deliberate resizing. Disclose unsupported properties; do not flatten the UI.
- For new destinations or organization, load [figma-file-organization](../figma-file-organization/SKILL.md). Build content inside its final parent from the outset; retain actual operation/parent evidence. A low-level empty node may attach immediately before population. No completed off-canvas design moved into a wrapper later.
- Batch the planned scoped edits. Retain mutation intent and returned IDs; after an ambiguous response inspect affected live state before retrying. Do not repeat normal inspections after each tool call.
- Place actual supplied/prepared assets with confirmed versions and crop/mask settings. Product photo requirements and mockup rules are in [Visual Release Checks](../figma-design-standards/references/visual-release-checks.md). Temporary imagery cannot pass required final-asset acceptance.
- A new/changed shared binding has scoped consumer impact; do not silently migrate unrelated work. Keep identity experiments separate from live definitions.

## After

Use one shared after pass for changed elements and direct dependencies, combining structural data and actual visual comparison. The two validation skills supply criteria, not mandatory separate reports or repeat inspections. Inspect required sizes/states within scope; reuse any already available result for this version. Apply release checks in this pass.

If an actual defect appears, correct it within scope and recheck only affected evidence under the shared budget. A new final image/text/control change invalidates affected checks, not the whole project. Unavailable checks stay explicit. Never rewrite requirements to excuse a failed design.

Store actual node mappings, changed bindings, operation evidence and links to canonical identity, direction/baseline, assets and the shared pass. Existing implementation records or task sections may hold these fields; do not copy selection analysis or review findings. Preview evidence goes to identity adoption; screen evidence goes to task acceptance without another inspection. `implemented` is not automatically accepted until required checks pass.
